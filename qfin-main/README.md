# 論文重現：QLSTM vs. QFWP、QLSTM＋QA3C

重現以下兩篇論文，使用 PennyLane（lightning.qubit、adjoint）＋ PyTorch：

- 實驗一：*Batched Training for QLSTM vs. QFWP: A System-Oriented Approach to EPC-Aware RMSE-DA*（ICASSP 2026，arXiv 2512.21820）
- 實驗二：*Quantum-Enhanced Forecasting for Deep Reinforcement Learning in Algorithmic Trading*（Globecom Workshops 2025，arXiv 2509.09176）

同一份程式在兩台電腦上各從頭跑過一次：

| | Mac | Windows |
|---|---|---|
| 硬體 | MacBook Air（Apple M4、10 核心、16 GB）。無風扇，長時間執行可能降頻，影響計時 | AMD Ryzen 9 9950X3D（16 核 32 緒）、32 GB |
| 系統 | macOS 26 | Windows 11 Pro，原生 Python 3.11（不用 WSL） |
| 套件 | PennyLane 0.45.1、PyTorch 2.14.1 | 相同 |
| 結果 | `results/` | `results_win/`（紀錄在 `logs_win/`） |
| 詳細報告 | 本頁 | [REPRODUCTION_WIN.md](REPRODUCTION_WIN.md) |

論文的實驗環境：Intel Core Ultra 7 265K、96 GB、Windows 11 + WSL2（Ubuntu 24.04）。

## 結論

- **實驗一：主要結論大致重現，但有幾項沒重現。**
  - QFWP 在 batch 4～64 的 DA 都高於 QLSTM，兩台電腦的 Wilcoxon p 都 ≤ 0.004，與論文一致。
  - QFWP 在 batch 16～64 的 RMSE、DA 和論文很接近（例如 batch 16：RMSE 0.00301 vs. 論文 0.0029）。
  - RMSE 的顯著性不穩定：Mac 只有 batch 64 不顯著（p = 0.084），Windows 連 batch 4 也不顯著（p = 0.064）。原因是 QFWP 偶爾會訓練崩掉，而且哪個種子會崩，換一台電腦就不一樣。
  - QLSTM 不像論文那樣隨 batch 變大而明顯變差；小 batch 的 DA 比論文低 6～8 個百分點。
  - 整體訓練加速比在 batch 32 左右就不再增加，和論文一致；但飽和值比論文高（Windows：QLSTM 約 2.5 倍、QFWP 約 2.75 倍），而且每個 batch 都是 QFWP 較高，和論文「QLSTM 加速比最高」相反。
  - 把 adjoint 梯度改到反向才計算（`device_vjp=True`）後，QLSTM「前向約 2.2 倍、反向約 1.2 倍、整體約 2 倍」的模式和論文相符；QFWP 的反向仍比論文快很多。
- **實驗二：沒有重現。** 只有模型架構和參數量與論文相同（QA3C 244、A3C 3,332）。
  - QLSTM 預測器準確率 60.2%（兩台電腦完全相同），論文約 71.5%。
  - 古典 A3C 總報酬 9.25%（兩台電腦各 3 個種子，平均都是 9.25%），與論文的 11.42% 同一量級；但交易約 437 次、勝率約 81%（論文 230 次、55%），交易方式不同。
  - QA3C 在 Windows 跑了 3 個種子：2.54%、0%、0%，後兩個在測試期間一次都沒交易，平均 0.85%。遠低於 A3C，也低於買進持有（6.92%），與論文「QA3C 比 A3C 高 0.45%」相反。Mac 只跑了 1 個種子（2.47%），剛好是有交易的那種。
  - 論文 Table V 的 ETF 報酬不是它自己寫的測試期間，比較基準不一致。
- **資料**：Yahoo 匯率日線的高低價會洩漏隔日收盤的資訊。一個零參數的規則（當日高低價的中點）DA 就有 66.8%，實驗一約 70% 的 DA 大多來自資料本身，不是模型的預測能力。

## 論文沒做、本重現額外做的事

1. **加入基準模型**：論文只比較兩個量子模型。這裡另外加了隨機漫步、同樣 hidden 大小的古典 LSTM，以及零參數的規則「ŷ = 當日 (High + Low) / 2」。古典 LSTM 的 DA（68.6%～69.7%）和 QFWP 差不多，零參數規則也有 66.8%，因此發現了資料的前視問題。
2. **檢查資料的前視**：比較 Close 與 Open（中位數只差 1.3 bp）和一天的高低價差（中位數 63 bp），並把同一個規則改用前一天的 High/Low，猜中隔日方向的比例從 72.1% 降到 51.8%。
3. **兩種獨立實作交叉驗證**：除了論文用的 PennyLane，另外用 NumPy 自己寫了狀態向量模擬器與反向自動微分（`ad.py`），兩者的輸出與梯度差在 1e-15 量級（`pl_check.py`）。
4. **掃描最佳化器與學習率**：論文沒寫。用 batch 4、16 和 3 個種子掃描 9 組設定（`sweep1.py`），選出最接近論文的 Adam、lr 0.05。
5. **換一台電腦重跑**：同一份程式、資料、套件版本和種子，在 Apple ARM 與 x86 各跑一次，檢驗結果能不能重現。QLSTM 兩台幾乎相同，QFWP 有 18 次訓練結果不同。
6. **補充計時實驗**：主實驗的計時方式量不到論文「反向是瓶頸」的主張，所以另外用 `device_vjp=True` 把 adjoint 梯度移到反向計算，重新量前向、反向、推論的加速比（`pl_exp1_timing.py`）。
7. **實驗二多跑種子**：論文每個模型只報告一次結果。這裡 A3C 在兩台電腦各跑 3 個種子，QA3C 在 Windows 跑 3 個種子，看結果是否穩定。
8. **更多評估指標**：除了論文的報酬、回撤、交易次數、勝率，另外記錄 Sharpe、持倉時間比例、每種動作的次數、訓練期報酬和買進持有基準；預測器另外記錄多數類別基準與 balanced accuracy。
9. **資料清理**：偵測並刪除 Yahoo USD/TWD 的 10 列錯誤報價（例如 2011-10-26 單日 +1571%）；特徵縮放只用訓練期間估計，不偷看測試期間的範圍。
10. **核對論文的 ETF 基準**：用實際價格計算測試期間的報酬，發現和論文對不上；再逐日搜尋 5 年期間，找到最吻合的是到 2025-07-21 為止的 5 年。
11. **核對論文的參數量與描述**：由 Table II 的 212 個古典參數，反推出 actor、critic 各需要一組投影層與 VQC；並整理出論文前後矛盾和沒寫清楚的地方（見下文）。
12. **讓 A3C 能在 Windows 原生執行**：原程式用 `fork` 建立 worker，Windows 沒有 `fork`。改成 `spawn`，在 worker 內重建網路並接上共享記憶體，並驗證共享參數與 Shared Adam 的狀態確實有被更新。

### 換一台電腦，QFWP 的結果就不同

同一份程式、資料、套件版本和種子，兩台電腦有 18 次 QFWP 訓練結果不同（non-batch 10 次全部、batch 4 有 6 次、batch 8 有 2 次）；QLSTM、古典 LSTM 和 batch 16 以上的 QFWP 則幾乎完全相同。差別只在 Apple ARM 與 x86 的浮點運算細節，更新步數越多（batch 越小），差異被放大得越多。

QFWP 在 lr 0.05 下的結果是二選一：收斂（RMSE 約 0.003）或崩掉（RMSE 約 0.0063～0.0066）。哪個種子會崩，換電腦就會變：

| 崩掉的種子數（RMSE 比隨機漫步差） | non-batch | 4 | 8 | 16 | 32 | 64 |
|---|---|---|---|---|---|---|
| QFWP Mac | 3 | 1 | 0 | 0 | 0 | 1 |
| QFWP Windows | 6 | 1 | 0 | 0 | 0 | 1 |

所以論文「所有 batch 都顯著」的結論，在 batch 4、64 取決於有沒有剛好碰到崩掉的種子，並不穩定。

主實驗的量法和論文不同，所以各部分對不上：

- **Forward／Backward**：PennyLane 的 adjoint 預設在前向計算時就一起算梯度，所以 Train-Forward 佔了約九成的時間，Backward 只剩 PyTorch 的部分。論文的 Train-Forward、Backward 加起來（例如 QLSTM batch 4：18.77 + 1.36 秒）遠小於 Full-Train（228.51 秒），計時範圍應該也不同。
- **Inference**：主實驗的推論一律用 batch 256，所以加速比約 1 倍；論文比的是 batched 與 non-batched 兩種實作。

**補充實驗**（Windows，`pl_exp1_timing.py`，3 個種子）：用 `device_vjp=True` 讓前向只做模擬、adjoint 梯度在反向才計算；推論用和訓練相同的 batch 大小（non-batch 為逐筆）。梯度和預設模式的差 ≤ 6e-17，只是計算的時間點不同。

- 這個模式比預設慢（QLSTM 整體 299～370 秒，預設 188～255 秒），所以只能比加速比，不能比秒數。

### 實驗二無法完全重現的可能原因

根據論文內容與本次結果推論出的可能原因，尚未經實驗驗證。要確認差異來自哪一項，需要做敏感度實驗或取得原始程式碼。

1. **決定交易行為的設定沒寫**
   - 初始資金與每單位大小：論文只寫「現金足夠就買 1 單位」。由 Fig. 2 的損益（最後超過 $5,500）推算，本金約 $46,000～50,000，但沒寫每單位多大。這會決定最多能加碼幾次、何時變成無效動作。
   - 無效動作的罰分（只寫「minor penalties」）、episode 的定義、測試時選最大機率還是抽樣、VQC 的層數與閘的排列、QLSTM 的 batch size。
   - pnl% 的單位：本次把 1% 當作數值 1（獲利 0.5% 出場的獎勵為 +10 + 50×0.5 = 35，截斷為 30）。若作者使用 0.01，獎勵約為固定 +10，代理人的行為會明顯不同。
2. **論文內容前後矛盾，只能擇一**
   - 虧損出場：Table III 為 −2 − 10×pnl%，依字面虧損時會得到正獎勵；Discussion 又寫固定 −2。
   - Algorithm 1 寫在測試資料上更新 QA3C；若實際如此，測試期間等於持續學習，結果不會和只用訓練期間訓練的版本相同。
   - 文字寫一個 VQC，參數量需要兩個 VQC 才對得上。
3. **資料不同**：論文資料從 2000 年開始，Yahoo 只從 2004 年開始，且有錯誤報價需刪除。資料不同使 QLSTM 預測器的輸出不同（60.2% vs. 約 71.5%），而它的輸出是代理人狀態的一部分。
4. **結果主要由獎勵設計決定，而不是模型**
   - 修正狀態定義前後，A3C 的結果幾乎不變（9.16% → 9.25%），且從不選擇「持有」，代表決策幾乎不依賴狀態。
   - 論文中 A3C 與 QA3C 的最大回撤（0.92%）、最佳單筆（0.61%）、最差單筆（−0.88%）完全相同，交易次數只差 1 次，也代表兩個不同網路做出幾乎相同的交易。
   - 因此只要上述未說明的設定有差異，交易次數、勝率、報酬就會跟著改變，只對上模型架構無法重現結果。
5. **本次實作可能與作者不同**：上述未說明的設定都是本次自行決定，任何一項與作者不同都會造成差異。交易環境沒有可對照的標準答案，也無法排除實作上的錯誤。
6. **強化學習的隨機性**：論文每個模型只報告一次結果，未說明執行了幾個種子。A3C 在兩台電腦的 6 個種子結果很接近（8.96%～9.53%），但 QA3C 的 3 個種子差異很大（2.54%、0%、0%），單一種子的結果不具代表性。

## 觀察到的

1. **匯率資料的前視偏誤**：Yahoo 匯率日線的 Close 約等於 K 棒開始時的價格（和 Open 的差距中位數 1.3 bp，一天的高低價差中位數 63 bp），但 High/Low 涵蓋整天。不用任何模型，只比較當日高低價中點和收盤，就能猜中 EUR/USD 隔日方向 72.1%（整段期間），改用前一天的 High/Low 只剩 51.8%。直接拿中點當預測，在測試集上 RMSE 0.00323、DA 66.8%（論文的定義）。古典 LSTM 也有 69%，所以實驗一約 70% 的 DA 主要來自資料。實驗一的訓練樣本數和論文完全相同，論文應該也是用 Yahoo 的資料。
2. **QLSTM 的差距集中在小 batch**：論文的 QLSTM 隨 batch 變大明顯變差，本次幾乎不變。學習率是依 QFWP 的結果選的，未必適合 QLSTM。
3. **前向與反向的計時方式**：PennyLane adjoint 預設在前向時計算梯度，所以主實驗看不到「前向快、反向慢」的不對稱。lightning.qubit 會忽略 `grad_on_execution=False`，要用 `device_vjp=True` 才會把梯度移到反向；這樣量出的 QLSTM 加速比和論文相符，QFWP 則不符。
4. **QFWP 的結果換電腦就變**：在 lr 0.05 下，QFWP 不是收斂就是崩掉，而浮點運算的微小差異就能改變走向哪一邊。只用 10 個種子，在 batch 4、64 的顯著性會因機器而不同。
5. **實驗二的代理人都不選擇「持有」**：A3C 一直在買和賣之間切換，所以交易次數約為論文的兩倍（約 437 vs. 230）、勝率偏高（約 81% vs. 55%）。QA3C 改用無效的「賣出」來空手觀望，3 個種子中有 2 個在測試期間完全不交易。每日 −0.02 的時間成本和每次獲利出場 +10 的獎勵，讓頻繁的小額獲利出場最划算；這個行為對初始資金、部位大小、無效動作罰分等論文未說明的設定很敏感。
6. **論文 Table V 的期間和測試期間不同**：ETF 報酬最吻合的是到 2025-07-21 為止的 5 年，和代理人的測試期間（到 2025-04-30）不一致。

## 執行時遇到的問題

1. **Windows 沒有 `fork`**：`pl_exp2.py` 的 A3C 原本用 `fork` 建立 worker，Windows 原生 Python 不支援。改用 `spawn` 時，QNode 無法 pickle，所以改成只傳共享記憶體裡的參數和 Shared Adam 狀態，在 worker 內重建網路再接上。已驗證父行程的參數會被更新，共享的 Adam step 數也和預期完全相同。Linux／macOS 仍用 `fork`。
2. **已有結果會被略過**：`pl_exp1.py` 遇到已存在的結果檔會直接略過，換一台電腦重跑會什麼都不跑。所以在 `common.py` 加上環境變數 `QFIN_RES`，可另外指定結果資料夾。
3. **`grad_on_execution=False` 沒有作用**：lightning.qubit 的 adjoint 會強制在前向就算梯度。要把梯度移到反向，必須用 `device_vjp=True`（`pl_models.py` 新增此選項，預設關閉，主實驗結果不受影響）。
4. **QFWP 訓練不穩定**：lr 0.05 下，QFWP 的部分種子會崩掉（RMSE 比隨機漫步還差），而且崩掉的種子換電腦就不同，見上文。
5. **QA3C 收斂不穩定**：3 個種子中有 2 個退化成永遠不交易；到 1,600 個 episode 獎勵仍在上升，訓練量可能不足。
6. **Windows 主控台編碼**：終端機預設 cp950，印出部分字元（例如 ŷ）會出現 UnicodeEncodeError，需要設定 `PYTHONIOENCODING=utf-8`。
7. **Windows Defender 的受控資料夾存取**：開啟時會擋住 Git Bash 的 `cp`、PowerShell 等程式寫入「文件」底下的資料夾（包括 GitHub Desktop 的預設位置）。可改用檔案總管複製，或在 Windows 安全性把程式加入允許清單。
